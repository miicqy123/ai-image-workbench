# 画布产品增强改造方案（对齐截图参考）

> 参考来源：5 张截图的「AI 商品主图批量输出」工作流（即创 / 稿定 / 万相实验室类）。
> 目标：在不推翻现有 React Flow 架构、不引入新依赖的前提下，吸收截图里**最值得借鉴**的三块能力。
> 本文件为方案稿，**改动将在你确认后执行**。

---

## 改造 A：策略方案结构化（对齐截图「策略方案」卡片）

### 借鉴点（截图 1、2、4）
截图里的策略卡不是简单三元组，而是包含：
- 需求摘要 / 统一品牌调性 / 用户风格
- 统一配色 / 统一材质光影 / 统一成像方式 / 目标比例
- 每个卖点的**卖点证明**（文字如何被视觉呈现）
- 画面骨架（构图 / 视角）/ 场景搭配库 / 产品位置
- 文字与信息模块（标题 / 卖点 / 政策 / 角标）

### 现状差距
`backend/app/generators/text.py` 的 `generate_strategy` 只产出 `ROLE_TEMPLATES` 三元组（role/卖点/人群/场景/构图/画幅），缺上述结构化字段，导致下游提示词较"空"、策略卡不可直接用于排版审核。

### 具体改动
**1) `text.py` — `generate_strategy` 返回结构升级**（向后兼容，新增字段）：
```jsonc
{
  "product_id": "...",
  "requirement_summary": "为居家用户提供温暖治愈的木作家具主图，调性偏自然、低饱和",
  "visual_baseline": {
    "palette": ["暖木色","奶油白"],
    "material_light": "柔光漫射，强调木质纹理与哑光质感",   // 新增
    "imaging_mode": "棚拍 + 轻场景合成",                    // 新增
    "locked_features": ["外壳颜色","旋钮位置"]               // 取自事实卡 locked_appearance
  },
  "target_aspect": ["1:1","4:3"],                            // 新增：统一目标比例
  "strategies": [
    {
      "id":"hero_1", "role":"主图", "selling_point_id":"sp1", "selling_point_text":"...",
      "audience":"居家用户", "scene":"纯色棚拍", "composition":"主体居中，留标题安全区",
      "aspect_ratio":"1:1",
      "proposition_proof":"用木纹特写 + 暖光体现‘天然材质’卖点",  // 新增：卖点证明
      "scene_options":["纯色棚拍","轻北欧客厅一角"],            // 新增：场景搭配库
      "product_placement":"居中偏下",                          // 新增：产品位置
      "text_modules": {                                       // 新增：文字信息模块
        "headline":"夏日焕新价", "selling_point":"天然木作·健康家居",
        "policy":"以旧换新补贴", "badge":"官方旗舰"
      }
    }
  ]
}
```
**2) `text.py` — `generate_prompt` 引用新字段**：把 `material_light` / `imaging_mode` / `proposition_proof` / `text_modules` 拼进正向提示词，使出图更接近"成稿"而非"空场景"。

**3) `main.py` — 策略节点运行入参**：让策略节点的 `content.task_brief`（`{goal, channel, audience}`）参与 `generate_strategy`，现在它一直是空 `{}`，需在 NodePanel 事实卡保存时一并写入或从策略节点补充编辑。

**4) `NodePanel.tsx` — strategy 节点展示升级**：用折叠分组渲染「需求摘要 / 视觉基线 / 各策略卡（卖点证明、场景搭配库、产品位置、文字模块）」。

### 验收
- 运行策略节点后，右侧面板能看到"需求摘要 + 配色/光影/成像方式 + 每张图的卖点证明与场景搭配库"。
- 下游提示词自动包含光影/成像方式/卖点证明描述。
- 旧数据（无新字段）仍可读，不报错。

### 风险
- 属纯字段扩展，不改接口签名，零回归。

## 改造 B：节点悬浮工具栏 + 图片处理意图（对齐截图 2、5）

### 借鉴点（截图 2、5）
- 节点 hover 出现工具栏：**替换 / 改图 / 抠图 / 消除 / 变清晰 / 扩图 / 改字 / 更多**
- 工具下方有"图片处理意图"分类：**商品图 / 相似图 / 转矢量 / 图文分层 / 溶图 / 变体 / 风格迁移 / 妙手库**

### 现状差距
现在节点运行结果只能在右侧面板看，节点本体只会显示缩略图，没有"就地操作"。模型能力里已有 `editing_modes`（text_overlay / inpaint / img2img），但前端没把"意图"暴露成按钮。

### 具体改动
**1) 概念新增「图片处理意图 → 模型能力」映射**（不改表结构，前端常量 + 后端校验复用 `validate_image_params`）：
| 意图 | 对应 editing_mode / 任务 | 真实可用？ |
|---|---|---|
| 改字 | text_overlay | ✅ local-poster-compositor |
| 抠图 | inpaint | ⏸ comfyui-product-edit（disabled） |
| 消除 | inpaint | ⏸ 同上 |
| 变清晰 | upscale（新增 mode） | ⏸ 占位 |
| 扩图 | outpaint（新增 mode） | ⏸ 占位 |
| 商品图 / 相似图 / 风格迁移 / 溶图 / 变体 | img2img | ⏸ 占位 |
> 说明：替换 / 排版 / 导出 走现有流程；其余意图若对应适配器 disabled，则按钮置灰并提示"该能力尚未接入，请在模型管理启用并接入适配器"。

**2) 后端 `generators/image.py` 新增**：
- `dispatch_tool(intent, asset_ids, model_id, params) -> {outputs, usage}`：按意图路由到对应处理（真实仅 text_overlay/合成；其余走占位返回"未接入"友好错误）。
- `registry.py` 的 `capabilities` / `validate_*` 增加 `upscale` / `outpaint` 两个 mode 的兜底识别。

**3) 后端 `main.py` 新增接口**：
- `POST /api/image-tools/run` `{ node_id, intent, asset_id, model_id?, params? }` → 执行某个图片处理意图，写回节点 `content.last_tool` 与图层。
- `GET /api/image-tools/intents` → 返回意图清单与每个意图的可用模型（供前端禁用灰化）。

**4) 前端 `App.tsx` 自定义节点组件**：
- 给 `image_generation` / `product_image` / `layout_export` 节点加 hover 浮层工具条（CSS `:hover` 显示，绝对定位在节点右上角）。
- 工具条按钮：替换 / 改字 / 抠图 / 消除 / 变清晰 / 扩图 / 更多(菜单：复制 / 锁定 / 导出 / 删除)。
- 点击"改字/抠图…"调用 `POST /api/image-tools/run`。
- 满足 `deleteKeyCode=null` 的现有约束：工具条里"删除"走后端接口，不用键盘。

**5) `styles.css` 补充**`.node-toolbar` / `.node-toolbar button` / 灰化态样式。

### 验收
- 鼠标悬停生图节点，右上角出现工具条；"改字"可用（调 text_overlay 真实生效），"抠图/消除/变清晰/扩图"在未接入模型下置灰并给提示。
- 点击"改字"能就地改文字并写回图层，无需回右侧面板。
- 启用 `comfyui-product-edit` 后，"抠图/消除"自动变为可用。

### 风险
- 接口与前端为新增，不影响现有 run 流程。
- "真实抠图/消除/扩图"依赖你本地 ComfyUI/workflow，属后续接入项，本改造只把**入口与置灰逻辑**打通。

## 改造 C：底部全局模型选择器（对齐截图 3）

### 借鉴点（截图 3）
底部常驻 AI 模型选择条（豆包 2.0 Lite / Pro / 千问 3.5 Plus + 计费），运行节点默认用全局所选，也可在节点单独覆盖。

### 现状差距
模型只有在节点面板里单独选（生图节点有 model_id 下拉）；没有"全局默认"。每次新建节点都要重选。

### 具体改动
**1) `db.py` — `projects` 表加两列**（init_db 兼容已存在库：用 `ALTER TABLE` 仅在缺列时加）：
- `default_text_model TEXT`
- `default_image_model TEXT`

**2) 后端 `main.py` 新增**：
- `GET /api/projects/{pid}/defaults` → `{default_text_model, default_image_model}`
- `PUT /api/projects/{pid}/defaults` `{default_text_model?, default_image_model?}` → 保存
- 节点运行（`strategy` / `image_prompt` / `image_generation`）若未显式传 `model_id`，自动回退到项目默认（再回退到内置默认）。

**3) 前端 `App.tsx` 底部 AI 指令条旁加全局选择条**：
- 两个下拉：文本模型（enabled text）、图片模型（enabled image），旁显示 `cost_policy`（如 free_local / per_image）。
- 选择后 `PUT defaults`，存入后端（同时 localStorage 做前端缓存防抖）。
- 顶部新建项目后自动读取默认值回填。

**4) `api.ts` 加 `getDefaults` / `setDefaults`。

### 验收
- 底部出现"文本模型 / 图片模型"两个下拉，显示计费策略。
- 选全局模型后，新建生图节点默认用它；节点面板仍可单独覆盖。
- 切换项目后全局选择条回填该项目保存的默认值。

### 风险
- 仅加列 + 加两个轻接口，不影响现有显式传 model 的逻辑（显式优先）。

## 实施顺序建议（确认后）
1. **改造 A**（策略结构化）— 纯后端+面板，风险最低，先吃收益。
2. **改造 C**（全局模型选择器）— 小接口+底部 UI，体验提升明显。
3. **改造 B**（悬浮工具栏+意图）— 改动最大，最后做；先把"改字"真实打通，其余意图置灰。

## 共用注意事项
- 三块都不引入新 npm / pip 依赖，全部复用现有 React Flow + FastAPI + Pillow。
- 所有"未接入能力"一律**灰化 + 友好提示**，不捏造路由（与现有 PRD 契约一致）。
- 改动后跑一遍 `e2e_test.py` 与前端 `npm run build` 确保零回归。
